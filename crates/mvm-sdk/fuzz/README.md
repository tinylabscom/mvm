# mvm-sdk fuzz target

This standalone fuzz crate hardens the runtime-recording parser and lowering
path in `mvm-sdk`. Runtime recordings are generated by user-launched code and
then read by the CLI, so their JSON must be treated as untrusted input.

## Who uses it

SDK and security contributors run this target when changing recording schemas,
operation limits, file-write decoding, or workload lowering. Security CI
compiles the harness when fuzz surfaces change. It is test-only and is not part
of any SDK package or mvm binary.

## How it works

`fuzz_runtime_recording` feeds arbitrary bytes to strict JSON deserialization
and, for accepted records, through the production lowering logic. The committed
minimal seed gives mutations a valid starting shape.

The harness explores unknown fields, duplicate paths, missing entrypoints,
oversized operation lists, malformed base64 file contents, and inconsistent
operations. Every refusal must be an error rather than a panic, and invalid
recordings must never become a canonical workload.

## Running it

From this directory, with nightly Rust and `cargo-fuzz` available:

```bash
cargo +nightly fuzz run fuzz_runtime_recording
```

Append `-- -max_total_time=300` for a bounded smoke run or `-- -runs=0` to
replay the existing corpus only.

## Workspace relationship

The package is excluded from the root workspace and declares an empty local
`[workspace]`, keeping `libfuzzer-sys` out of normal builds. Its manifest also
repeats the vendored `arrayref` patch because standalone dependency graphs do
not inherit the root patch table.
