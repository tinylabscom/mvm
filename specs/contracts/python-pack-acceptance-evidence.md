# Python pack acceptance evidence

Backing: preview
Validation: none — this records evidence for the parent issue; it is not a claim of complete enforcement.

This reconciles the acceptance criteria of [#4224](https://github.com/tinylabscom/mvm/issues/4224)
against landed code and one native run. The issue owns status. "Witnessed" names
a test that exists; every limit is stated rather than implied.

## Acceptance evidence and its limits

| Criterion | Evidence | Limit |
|---|---|---|
| Deterministic source snapshot and exact package/dependency pins | `locking_is_deterministic_for_an_unchanged_tree` and `a_fresh_lock_compiles_from_the_verified_snapshot` (`mvm-compiler` `pack/frozen.rs`); `lowering_is_deterministic` (`pack/lower.rs`); symlinks that escape the tree are refused (`a_symlink_escaping_the_source_tree_is_refused`) | Determinism is witnessed for an unchanged tree on one host, not across hosts. |
| Python dependencies resolved with hashes; unavailable versions fail | `a_uv_lockfile_compiles_to_its_resolved_wheel_set`, `an_sdist_only_package_is_refused_by_name_and_version`, `the_chosen_wheel_must_be_https_and_sha256_pinned`, `an_unavailable_package_version_is_refused_before_anything_is_written`. Native: a uv lock for `six==1.17.0` locks and compiles to `pack-build.json` carrying wheel sha256 `4721f391ed90541fddacab5acf947aa0d3dc7d27b2e1e8eda2be8970586c3274`; stripping the hashes is refused at lock time ("not hash-pinned: 1/2 packages missing hash"); a lock whose wheel names another version is refused ("wheel ... is not version 1.17.0") | Resolution reads a uv lockfile; nothing resolves against an index. A lock edited consistently to a version that does not exist on the index passes `pack lock` and fails only when the builder fetches the wheel. |
| Extend existing compiler and Nix factories | The wheel install is generated by the existing flake renderer in `mvm-compiler` (`flake.rs`, `a_pack_build_file_installs_its_locked_wheels_at_build_time`); no second renderer exists | None beyond the dependency-boundary regression that already pins the compiler. |
| Custom Nix modules and build scripts are not supported in the locked package path in this version | `a_spec_has_no_nix_module_or_build_script_to_execute` (`mvm-contract` `tests/pack_spec.rs`): a spec that names `nix_module`, `build_script`, `install_script` or `hooks` fails to parse; sdist-only packages are refused by name and version | Owner decision (2026-10-20): no escape hatches in this version. A future escape hatch needs its own design with recorded digests and restricted execution. |
| Frozen builds refuse stale locks; build and runtime packages separated | `a_changed_wheel_hash_stales_the_lock`; `build_scoped_packages_stay_out_of_the_image_and_into_the_digest` | Separation is witnessed in the generated flake and workload digest, not by inspecting a built build-scoped package. |
| No secrets or ambient host paths; lock, schema and error fixtures; native build witness | Fixtures under `crates/mvm-compiler/tests/fixtures/pack-python`; `a_copy_outside_the_application_tree_is_refused_before_snapshot`. Native, aarch64 macOS, HVF builder: `machine build --flake <compiled pack> --prod` exited 0 and the built `rootfs.ext4` contains `hello4224y-python-deps-0/lib/python3.12/site-packages/six.py` and `six-1.17.0.dist-info`; the flake fetches the wheel as a fixed-output derivation pinned to the lock's sha256, which the builder checks; the wheel downloaded from the lock's URL hashes to the same value | The built image was not booted, so `import six` in the guest is unwitnessed. `pack build` (compile, build, health boot, sign) did not run: it stops fetching `mvm-guest-bins-v0.24.0.tar.gz` (HTTP 404, no such release asset), and signature verification was not bypassed. The wheel was located by string search in the ext4 image, not by mounting it. |

## Native run

Host: macOS arm64, HVF builder, a debug `mvmctl` from main with the builder start
fixes in. Steps: `pack lock` and `pack compile` of a project whose uv lock pins
`six==1.17.0`; `machine build --flake <out> --prod` (exit 0, 5m20s on a warm
home); `pack build` (exit 1, missing release asset above).

## What closes this

The native build witness of a Python pack is met by `machine build --flake`
only in the sense of building the compiled pack's image. The end-to-end
`pack build` witness needs a published `mvm-guest-bins` release asset for the
running version. Until it exists, the issue stays open.

## Re-run on main

The named tests in the table above were re-run scoped (`mvm-compiler`,
`mvm-contract`) and pass. Unmet bullets: the end-to-end native `pack build`
witness plus a guest import of the locked wheel (blocked on the
`mvm-guest-bins` release asset and a native boot). The escape-hatch criterion
is decided as not supported in this version.
