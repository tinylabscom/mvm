# Plan 142 — Network no-bypass hardening: disable libkrun implicit-vsock (TSI) + close the Cardoso egress holes

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove and close the *covert-egress* surfaces under **claim 10** (ADR-058 / ADR-002 §"No untrusted workload reaches the network unless explicitly admitted"). The headline: libkrun's **implicit vsock is the TSI transport** — a host-network path that sidesteps virtio-net and the default-deny egress gate. The `tsi` *mode* was removed (Plan 102 W6.A) but the *transport* may persist on the workload launch path. Audit it; if reachable from the guest, disable it via `krun_disable_implicit_vsock` (which libkrun's own author does in `slp/krunai`). Then execute Plan 111 Workstream A's never-run "egress remainder" (DNS / broker / vsock control-plane carve-out) against the existing gate.

**Architecture:** The workload launch path is `crates/mvm-libkrun/src/lib.rs` (libkrun ctx build) → `crates/mvm-libkrun/src/sys.rs` FFI. mvm routes real traffic through gvproxy(macOS)/passt(Linux) virtio-net with `NET_FLAG_VFKIT` (`lib.rs:699`) and reaches the guest agent over an **explicit** vsock port (`add_vsock_port2`, listen path, `sys.rs:257`). The *implicit* vsock is a separate libkrun-default device; krunai shows `krun_disable_implicit_vsock()` and an explicit `krun_add_vsock()` coexist, so disabling the implicit one leaves the agent ping intact — which Plan 120's `core_demo_e2e` proves. The bindings are generated by `bindgen` from the installed `libkrun.h` (`crates/mvm-libkrun/build.rs`), so `krun_disable_implicit_vsock` must be present in the header (libkrun ≥ the version krunai pins, `krun-sys 1.10`).

**Tech Stack:** Rust (`mvm-libkrun`, `mvm-libkrun-supervisor` — rebuild with `--features libkrun-sys`), libkrun FFI, vsock, `examples/agent_ping` for the in-guest probe, `.github/workflows/security.yml` no-bypass lane (gate-wiring handed to Plan 128).

**Sequencing (hard):** the **code change in Task 1 Step 4 lands only after Plan 120 Task 4 (`core_demo_e2e`) is green** — that E2E is the regression guard proving the explicit agent vsock still pings after the implicit vsock is disabled. Stage-wise this is a Stage-D hardening plan, after the core demo (120) and network/storage (123) land; its CI gate is wired by Plan 128 (which runs last).

**Out of scope / deferred:** volume confidentiality + Noise/AES vsock framing (ADR-027/ADR-042 — encryption-at-rest, Plan 122; ADR-058 Legs 1 & 3). This plan is the egress *no-bypass* leg only, not encryption. Snapshot/restore egress interactions → Plan 140.

## Task 1: Audit + disable libkrun's implicit vsock (TSI transport)

- [ ] **Step 1 — bindings + version check.** Confirm `krun_disable_implicit_vsock` is exposed by the bindgen-generated bindings (grep the generated `bindings` / `libkrun.h`); confirm the installed libkrun provides it. If absent, that's a Homebrew-libkrun version floor to document in CLAUDE.md "Host dependencies".
- [ ] **Step 2 — read the launch sequence.** In `crates/mvm-libkrun/src/lib.rs` trace the full ctx-build order; determine whether the implicit vsock is left enabled at `krun_start_enter`. Record the answer with file:line.
- [ ] **Step 3 — red probe (the proof).** From a booted **workload** microVM (use the `examples/agent_ping` boot-verify convention) with egress policy default-deny, attempt a host-network connection over the implicit-vsock/TSI path. **Reachable == claim-10 bypass.** Run bounded + backgrounded (never a foreground blocking call — see Plan 120 Workstream A operating rule).
- [ ] **Step 4 — disable it (after Plan 120 green).** If Step 3 proves reachable, add `krun_disable_implicit_vsock` to the launch path. Re-run `core_demo_e2e` (`MVM_E2E_SMOKE=1`, bounded) → the explicit agent vsock must still ping. Rebuild the supervisor explicitly (`cargo build -p mvm-libkrun-supervisor --features libkrun-sys`) or it runs stale.
- [ ] **Step 5 — no-bypass regression.** Add a gated regression asserting the TSI path is unreachable under default-deny; hand the `security.yml` lane wiring to Plan 128's gate-building.
