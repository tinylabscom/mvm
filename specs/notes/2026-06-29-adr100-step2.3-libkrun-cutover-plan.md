# ADR-100 Step 2.3 — libkrun: delete the network plane, one vsock gateway

Steps 2.1 (extract `EgressProxy`) and 2.2 (in-guest `mvm-egress-client`) are done.
This is the file-level plan to take **libkrun** to the ADR-100 end state.

**End state (not a NIC swap).** No guest NIC, no IP stack beyond loopback, and **no
host network gateway layer**: passt, gvproxy, the in-house rvproxy, and the
nft/redirect terminator are all *deleted* for workload VMs. Every outbound flow is a
guest vsock stream to one host **egress gateway** that is the sole chokepoint and
does both jobs — the claim-10 allow/deny decision (`EgressGate`) **and**, for a
bound-secret destination, the claims-12/13 credential substitution the terminator
does today. The gateway proxies TCP; DNS resolves host-side via the pin registry;
UDP/QUIC/raw-IP get a datagram-over-vsock path only if scoped in (never a NIC).

This changes the claims-12/13 implementation (substitution moves off the NIC onto
the vsock path), so it is security-touching and needs review + a live libkrun boot
to verify. Execute it with review, not blind.

## What libkrun actually does today (the machinery to converge)

- `crates/mvm-backend/src/libkrun.rs`:
  - Attaches a **NIC** via `krun.with_gvproxy(...)` / `with_passt(...)` (the
    `resolve_networking_mode` arm, ~L185–193).
  - Already opens a **vsock `SUBSTITUTION_PORT` host-listen channel**
    (`add_host_listen_port(SUBSTITUTION_PORT)`, ~L168) and spawns a per-VM
    *substitution endpoint* (`substitution_spawn`, ~L63–82) — but that is the
    **credential-substitution** path (Plan 197 / claims 12–13), not general egress.
  - Threads `network_policy` (~L238–251) to the gateway-bridge, which enforces
    claim-10 on the **NIC** traffic (passt/gvproxy `PlanFlowPolicy` + scans).
- So libkrun enforces claim-10 *around the NIC*, and uses vsock only for the
  narrow substitution channel. ADR-100 flips this: claim-10 egress rides the vsock
  gateway, and the NIC goes away.

## Blocking refactor first: decouple `EgressProxy` from `Hdr`

`vmm::egress_proxy::EgressProxy` is the right decision+proxy core, but its API is
coupled to the in-house VMM's vsock `Hdr` (`handle_request(src_port, hdr, …) ->
Vec<(Hdr, op, bytes)>`). The libkrun consumer terminates a **host UDS** (libkrun's
vsock-over-UDS), not a virtio queue — `Hdr` is meaningless there. Before reuse:

**Done (commit 0c314c9a):** `EgressProxy` is now transport-agnostic — keyed by an
opaque `conn_id`, speaks raw bytes + a semantic `EgressAction`, returns
`(conn_id, bytes)` ready + closed lists from `drain()`; no `Hdr`, no vsock ops. The
in-house VMM device keeps a thin `conn_id→Hdr` adapter.

**Design correction (important).** Working the next slice clarified what is actually
shared. `EgressProxy::drain()` is **poll-based** — it fits the in-house VMM's
single-threaded run loop (drain on each heartbeat tick). A libkrun host-UDS bridge
is async/threaded and naturally pumps each connection with `copy_bidirectional`, not
a poll loop. So the **genuinely shared core is [`EgressGate`]** — the claim-10
decision (`decide_request("ip:port") -> Allow/Deny/Malformed`), which has been
shared from the start (it wraps `CanonicalEgress`). `EgressProxy` is the HVF/poll
wrapper around it; it is *not* the thing libkrun reuses.

So the libkrun host egress server is its own small async pump that reuses
`EgressGate`, mirroring the in-guest `mvm-egress-client` but on the host side:
accept UDS → read first frame (target) → `EgressGate::decide_request` (built from
the admitted plan's policy + DNS pins, same as HVF) → on Allow `TcpStream::connect`
→ `copy_bidirectional(uds, tcp)`; on Deny/Malformed close. No `EgressProxy` reuse,
no poll model. (`EgressGate` is already `pub`; nothing to promote.)

## Host side — `crates/mvm-vm-host/src/bin/mvm-libkrun-supervisor.rs` (+ libkrun.rs)

1. **Egress server task** (`mvm_vm_host::egress_server`, built + unit-tested): accept
   on the host UDS for the dedicated `EGRESS_PORT` (libkrun forwards the guest vsock
   connect to a host-bound UDS via `add_host_listen_port`; the UDS delivers the raw
   guest stream — confirmed, see findings), read the newline-terminated target,
   decide via `EgressGate::from_network_policy(admitted policy, DNS pins)` — same
   gate as HVF — and on Allow `copy_bidirectional` the UDS ↔ a fresh `TcpStream`.
2. **Fold claims-12/13 substitution into the gateway.** A bound-secret destination
   must get the placeholder→real-credential rewrite + the TLS terminator the
   `substitution_proxy` does today — but driven from the vsock egress flow, not the
   NIC's nft/redirect terminator. Either the egress server hands a bound flow to the
   existing `substitution_proxy` logic, or that logic becomes a mode of the gateway.
   This is the security-touching part that needs review (it changes how claims 12/13
   are wired), and it is the reason this is a unification, not a NIC swap.
3. **Delete the network plane** for workload VMs in `libkrun.rs`: remove the
   `with_gvproxy` / `with_passt` attach **and** the `transparent_terminator_port` /
   `egress_redirect` wiring (the terminator was fed off the NIC). passt / gvproxy /
   rvproxy / the nft-redirect terminator all go. The builder VM (not a workload)
   keeps its NIC — out of scope.

## Guest side — `nix/lib/mk-guest.nix` (+ a package)

1. Add `nix/packages/mvm-egress-client.nix` mirroring `mvm-addon-dns.nix` /
   `mvm-exit-report.nix` (static aarch64/x86_64-musl build of the new bin).
2. Bake it into the rootfs and **start it in `/init`** before the workload (it only
   needs `lo`, which init already brings up: `busybox ip link set lo up`).
3. Export `ALL_PROXY=socks5h://127.0.0.1:1080` (and `HTTP(S)_PROXY`) into the
   workload env so ordinary clients use it.
4. **Stop bringing up `eth0`** for workload images (there is no NIC). Behind a
   `mkGuest` flag during rollout so non-converged backends still get a NIC.

## DNS

`mvm-egress-client` forwards `socks5h` domain targets verbatim; the host
`EgressProxy` currently refuses non-numeric targets. Add host-side resolution
against the DNS pin registry (already in the supervisor) before admit, OR keep
`mvm-addon-dns` resolving in-guest and have the client send numeric IPs. Decide
before vz/FC — it is shared across all three.

## Live-session findings (2026-06-29) — these revise the approach

Investigating the libkrun boot environment (Homebrew `slp/krun` trio present:
libkrun 1.18.0 / libkrunfw 5.3.0 / gvproxy 0.8.8) surfaced three things, two of
which change the design:

1. **UDS wire framing CONFIRMED raw — no boot needed.** The existing, production
   substitution proxy (`mvm_hostd::supervisor::substitution_proxy`) reads its own
   14-byte app header (`RVPROXY_ORIGINAL_DST_MAGIC` + IP + port) directly as the
   first bytes off the libkrun host-listen UDS (`read_exact(&mut [0u8;14])` +
   magic check). That only works if libkrun forwards the **raw guest stream** with
   no libkrun-internal CONNECT/handshake prefix. So `egress_server`'s framing
   (read the newline target line straight off the UDS) is correct as written.

2. **Not a port collision — one egress port.** I first read the egress/substitution
   port overlap on 5253 as a collision needing a second port. It isn't: under the
   unification (finding 3) egress and substitution are **one service**, so they
   share **one** egress-gateway port. Substitution is a *behavior* of the gateway
   for bound-secret targets, not a separate channel/port. So there is no "split" —
   `SUBSTITUTION_PORT` is renamed `EGRESS_PORT` (same number, 5253, which was always
   host-mediated egress), and both HVF and libkrun's gateway answer on it. Each VM
   has its own vsock; the port is a fixed well-known service number reused per VM
   (not a secret, not per-VM-unique — isolation is the per-VM transport + policy).

3. **Claims 12/13 are NIC-entangled — the big one.** libkrun feeds egress through
   `with_gvproxy`/`with_passt` (the NIC) **and** a `transparent_terminator_port` +
   `egress_redirect` that intercepts `:80/:443` off that same NIC path to feed the
   substitution endpoint (claims 12/13). **Dropping the NIC removes the terminator's
   feed**, so credential substitution breaks unless it *also* moves onto a vsock
   channel. So the libkrun cutover is not "swap the NIC for vsock egress" — it is a
   **claims-10 + 12 + 13 unification onto vsock**: the vsock egress path must carry
   both general egress (claim 10, via `egress_server` + `EgressGate`) and the
   bound-host credential substitution (claims 12/13, the terminator/substitution
   logic, today fed by the NIC). That is a substantial, security-critical change
   that needs maintainer review before burning builder-VM boot cycles.

**Revised recommendation.** The framing unknown is resolved and the port question
collapsed to one egress port. Next desk-verifiable step: rename `SUBSTITUTION_PORT` →
`EGRESS_PORT` (same number; the const is now "the egress gateway port"), re-verify
the HVF echo. The NIC-drop is gated not just on a boot but on the claims-12/13
unification (finding 3) — a design call for review, not an autonomous cutover.
